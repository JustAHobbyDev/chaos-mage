# Core conceptual problem

The old validity gate effectively asks whether the proposed transfer can presently sustain its operation→signal→inference chain.

For a generator, this can be too strict.

Consider:

```text
procedure:
measure per-handoff timing differences
→ compare route responses
→ constrain hidden stage contributions
```

If the target does not yet contain per-handoff timestamps, that can mean:

```text
execution_readiness:
requires timestamps
```

without necessarily meaning:

```text
transfer_validity:
conditional
```

By contrast:

```text
assume observed motif similarity implies
causal propagation through a hidden medium
```

contains an unresolved inferential bridge.

That is not merely an execution prerequisite.

Experiment F must make this distinction explicit.

# New chain model

Use the following conceptual chain:

```text
mapped state
    ↓
mapped operation
    ↓
mapped signal
    ↓
evidential warrant
    ↓
mapped inference
    ↓
target contribution
```

The three validity questions become:

```text
MECHANISM FIDELITY
state → operation → signal

WARRANT VALIDITY
signal → inference

TARGET FIDELITY
inference → target question
```

Execution readiness is separate:

```text
Can the required state, data, measurement, intervention,
apparatus, records, controls, etc. presently be instantiated?
```

Do not treat execution readiness as another validity dimension.

# Condition taxonomy

Every unresolved condition must be classified into one of:

```text
execution_precondition
mechanism_condition
warrant_condition
target_fidelity_condition
mixed
uncertain
```

These categories are not a numerical scale.

---

# 1. Execution precondition

Definition:

> A condition concerning the ability to instantiate or run an otherwise coherent mapped procedure, where establishing the condition does not materially change the mapping's mechanism, evidential warrant, inference, or target question.

Examples:

```text
obtain timestamps
collect another record
calibrate a detector
run enough trials
gain access to historical versions
record route membership
establish a reference measurement
instrument the process
```

A condition is especially strong evidence for this category when it can be checked or satisfied **before relying on the resulting inference**.

Execution preconditions do **not** make prospective validity Conditional by themselves.

---

# 2. Mechanism condition

Definition:

> A condition whose truth determines whether the mapped state→operation→signal structure actually instantiates the source instrument's operational mechanism.

Examples:

```text
the compared sequences must actually share a common temporal process
the paths must actually traverse overlapping hidden components
the intervention must genuinely remove and restore the same relevant factor
the proposed phases must actually create differential retention behavior
```

If this remains unresolved, the transfer itself may only conditionally exist.

This is validity-relevant.

---

# 3. Warrant condition

Definition:

> A condition required for the mapped signal to justify the proposed inference.

Examples:

```text
the response must discriminate causal contribution rather than a confound
the inversion must be identifiable enough to constrain hidden components
the detected feature must be specific enough to support the historical inference
the residual must actually bear on the claimed hidden state
```

This is not just a requirement to obtain the signal.

It determines what the signal means.

This is validity-relevant.

---

# 4. Target-fidelity condition

Definition:

> A condition required for the mapped inference to bear on the retained target question.

Example:

```text
localized service contribution
→ which deployed change caused the production regression
```

If an additional bridge is needed between the mapping's conclusion and the actual target question, classify that bridge here.

This is validity-relevant.

---

# 5. Mixed

Use when one stated condition contains more than one inseparable kind of requirement.

Prefer splitting a condition into atomic clauses first.

Use `mixed` only when decomposition would materially distort the condition.

---

# 6. Uncertain

Use when available context does not establish which category applies.

Do not force a classification.

---

# Atomic-condition rule

Before categorization, split compound condition statements into the smallest units that can independently affect:

```text
execution
mechanism
warrant
or target fidelity
```

Example:

```text
"obtain route timestamps and verify that the inversion uniquely
localizes hidden delay"
```

should become:

```text
1. obtain route timestamps
   → execution_precondition

2. verify identifiability of the inversion
   → warrant_condition
```

Do not let compound wording obscure category distinctions.

---

# Critical boundary rule

A condition is **not** an execution precondition merely because it could in principle be tested.

The decisive question is:

> If the condition turns out false, does the procedure merely become unavailable/unexecutable, or does the proposed source→target mechanism or inference stop making epistemic sense?

If false means:

```text
cannot perform the procedure yet
```

it may be execution.

If false means:

```text
the signal would not mean what the mapping claims
```

it is warrant.

If false means:

```text
the source mechanism is not actually instantiated
```

it is mechanism.

If false means:

```text
the resulting inference does not answer the target question
```

it is target fidelity.

---

# Another important rule: checking may be part of execution

A mapping can include:

```text
verify precondition P
then perform operation X
```

without P automatically becoming a warrant condition.

If P is an ordinary readiness check establishing that the procedure can be instantiated, it may remain an execution precondition.

But if P is itself the evidence bridge that makes Y support Z, it belongs to warrant validity.

Judge functional role, not whether the condition is called a "check."

# Mechanism fidelity

Statuses:

```text
preserved
conditional
not_preserved
```

Question:

> Assuming required execution resources can be obtained, does the mapped state→operation→signal chain preserve the distinctive source mechanism?

`conditional` here requires a genuine unresolved **mechanism condition**.

Missing data/instrumentation alone does not justify `conditional`.

---

# Warrant validity

Statuses:

```text
supported
conditional
unsupported
```

Question:

> If the mapped operation produces the stated signal under the mapping's explicit conditions, does that signal support the stated inference?

`conditional` requires an unresolved **warrant condition**.

Examples of failures include:

```text
circular signal definitions
confound ignored by the claimed inference
non-identifiability presented as localization
association presented as causal contribution
detected feature presented as historical proof without a bridge
```

Do not reject merely because the signal has not yet been observed.

---

# Target fidelity

Statuses:

```text
addressed
conditional
not_addressed
```

Question:

> Does the mapped inference provide a justified answer or bounded contribution to the retained target question?

`conditional` requires an unresolved target-fidelity bridge.

Do not require the mapping to completely solve a broad target question.

A bounded contribution is allowed if its relationship to the target is explicit.

# No observed-outcome requirement

This is essential.

A prospective procedure can be Valid before it has been executed.

Example:

```text
operation:
remove suspected factor and later restore it

signal:
phenomenon disappears and returns

inference:
factor contributes under tested conditions
```

The absence of an observed disappear/reappear result does not itself make the **transfer design** Conditional.

The validity question is whether:

```text
if the operation yields that signal as defined,
the inference is licensed within the stated limits
```

Execution readiness separately records whether the operation can currently be performed.

---

# But do not permit hypothetical magic

Prospective validity does not mean:

> Any imagined signal may simply be assumed.

The mapped operation must provide a coherent way for that signal to arise.

The signal cannot be defined as:

```text
whatever observation proves the desired conclusion
```

and the warrant cannot be circular.

The mechanism and warrant remain testable objects of validity.
